# 学习协作系统测试分析（应届生软件测试项目）

## 1. 文档目的与审查范围

本文从软件测试初学者和应届生求职角度，对当前仓库进行功能梳理、测试点设计和代码风险分析。

- 审查依据：前端路由与页面、后端接口、数据库初始化代码、`package.json`。
- 审查方式：源码静态检查，并执行 `npm run lint`。
- 本次没有启动 MySQL、前端或后端，因此“代码中存在”不等于“运行验证通过”。
- 本次没有修改任何业务代码。
- 测试方法只使用基础方法：页面操作、等价类、边界值、错误输入、角色切换和简单接口检查，不涉及性能测试、自动化框架或渗透测试。

建议准备 4 个基础测试账号：

| 测试角色 | 用途 |
| --- | --- |
| 普通用户 A | 创建小组，作为组长 |
| 普通用户 B | 接受邀请，作为组员 |
| 普通用户 C | 不加入目标小组，验证越权访问 |
| 管理员 | 验证后台功能和普通用户访问后台的限制 |

## 2. 项目功能模块和主要页面

前端路由集中在 [`src/App.jsx`](../src/App.jsx#L77)，后端主要接口集中在 [`server/index.js`](../server/index.js)。

| 模块 | 页面/路由 | 实际代码中的主要功能 |
| --- | --- | --- |
| 入口与认证 | `/login`、`/register` | 登录、注册、保存登录令牌、按普通用户/管理员跳转 |
| 学习空间 | `/dashboard` | 当前用户的小组、任务、近期资料和统计图表汇总 |
| 小组列表 | `/groups` | 查看我创建/我加入的小组、创建小组、删除小组、退出小组 |
| 小组详情 | `/groups/:groupId` | 看板、成员、讨论、统计、资料 5 个标签页 |
| 任务中心 | `/global-tasks` | 汇总当前用户可访问小组的任务，按状态展示和搜索 |
| 消息通知 | `/notifications` | 查看消息、标记已读、接受/拒绝邀请、删除通知 |
| 全局资料库 | `/global-files` | 展示 `shared_files` 中的链接型资料 |
| 资料集锦 | `/all-files` | 展示 `group_files` 中的实际上传文件并支持搜索、获取 |
| 个人设置 | `/profile` | 修改昵称、简介、头像和密码 |
| 管理后台概览 | `/admin/overview` | 用户/小组/任务/文件统计、活跃小组、最新动态 |
| 用户管理 | `/admin/users` | 新增、编辑、查看、删除用户 |
| 小组管理 | `/admin/groups` | 查看、编辑、强制解散小组 |
| 任务监管 | `/admin/tasks` | 查看、编辑、删除全站任务 |
| 资料监管 | `/admin/files` | 查看、删除实际上传文件 |
| 小组排行榜 | `/admin/all-group-rankings` | 按讨论数、任务数、文件数计算小组活跃度排行 |

补充说明：

- [`src/pages/Home.jsx`](../src/pages/Home.jsx) 和 [`src/pages/AdminDashboard.jsx`](../src/pages/AdminDashboard.jsx) 当前没有接入路由，属于未使用页面文件，不应当作为已完成功能写入简历。
- 项目有两套资料数据：`shared_files` 保存资料名称和链接，`group_files` 保存真实上传文件。小组详情实际使用 `group_files`，而 `/global-files` 使用 `shared_files`，目前流程没有完全统一。

## 3. 各模块功能测试点

以下“预期结果”表示一个合理系统应有的表现；第 5 节会单独列出当前代码不符合预期的地方。

### 3.1 登录

代码依据：[`src/pages/Login.jsx`](../src/pages/Login.jsx)、[`server/index.js`](../server/index.js#L426)。

| 场景 | 测试点 | 预期结果 |
| --- | --- | --- |
| 正常 | 普通用户输入正确用户名和密码 | 登录成功，保存 token 和用户信息，进入 `/dashboard` |
| 正常 | 管理员输入正确用户名和密码 | 登录成功，进入 `/admin/overview` |
| 正常 | 登录后退出 | 本地 token 和用户信息被清除，返回登录页 |
| 异常 | 用户名不存在 | 提示“用户名或密码错误”，不暴露具体是哪一项错误 |
| 异常 | 密码错误 | 返回 401，页面不跳转，不保存 token |
| 异常 | 用户名或密码为空 | 前端阻止提交；直接请求接口时返回 400 |
| 异常 | 伪造、过期或签名错误的 token | 受保护接口返回 401 |
| 异常 | 后端未启动、网络异常、数据库异常 | 页面显示失败提示，按钮恢复可点击 |
| 边界 | 用户名前后有空格 | 用户名会被去除首尾空格后登录 |
| 边界 | 密码含空格、中文或特殊字符 | 密码应按原值校验，不应意外截断 |
| 边界 | 连续快速点击登录 | 提交期间按钮禁用，不应产生多次跳转 |
| 边界 | 服务重启后继续使用旧 token | 设置固定 `AUTH_TOKEN_SECRET` 时应继续有效；未设置时当前代码会使旧 token 失效 |

### 3.4 任务管理

当前任务状态只有“待处理、进行中、已完成”。用户端支持新增、修改状态、拖动状态和删除；管理员端还支持编辑内容。

代码依据：[`src/pages/GroupDetail.jsx`](../src/pages/GroupDetail.jsx#L474)、[`src/pages/GlobalTasks.jsx`](../src/pages/GlobalTasks.jsx)、[`server/index.js`](../server/index.js#L1663)。

| 场景 | 测试点 | 预期结果 |
| --- | --- | --- |
| 正常 | 在小组中新增三种状态的任务 | 任务进入对应看板列，统计同步更新 |
| 正常 | 点击菜单修改任务状态 | 数据库和页面状态一致 |
| 正常 | 将任务拖到另一状态列 | 状态更新成功，刷新后仍保持 |
| 正常 | 删除任务 | 确认成功后任务消失，统计数量减少 |
| 正常 | 在全局任务中心搜索内容或小组名 | 只显示当前用户可访问小组的匹配任务 |
| 异常 | 空任务、全空格任务 | 应拒绝创建 |
| 异常 | 非法状态值 | 接口返回 400，原任务状态不变 |
| 异常 | 不存在的任务 ID | 返回 404，不应仅返回 HTTP 200 的失败对象 |
| 异常 | C 读取、创建、修改或删除 A 小组任务 | 应返回 403；当前普通任务接口没有小组成员校验 |
| 异常 | 不传 `group_id` 获取任务列表 | 普通用户不应看到全站任务；当前接口会返回全部任务 |
| 边界 | 任务内容 1 字符、超长文本、中文和特殊字符 | 合法内容正确显示；超长应限制并提示 |
| 边界 | 连续快速新增或删除 | 不应产生重复任务或重复操作错误 |
| 边界 | 0 个任务 | 看板和统计正常显示 0，不出现除零或空白异常 |
| 边界 | 任务在三个状态间快速切换 | 最终页面状态应与数据库一致 |

当前项目没有任务负责人、截止日期、优先级、任务评论和用户端编辑任务内容，因此不要为这些不存在的功能编写“已完成”测试结论。

### 3.5 讨论

代码依据：[`src/pages/GroupDetail.jsx`](../src/pages/GroupDetail.jsx#L547)、[`server/index.js`](../server/index.js#L2418)、[`server/index.js`](../server/index.js#L60)。

| 异常 | C 获取 A 小组讨论历史 | 应返回 403；当前接口只校验登录，不校验成员关系 |
| 异常 | C 向 A 小组发送消息 | 应返回 403；当前代码反而会把 C 自动加入小组 |
| 异常 | 未认证 Socket 连接加入房间 | 应拒绝；当前 `join_group` 没有 token 和成员校验 |

注意：当前 `@成员` 主要是前端显示格式，后端没有根据提及内容创建通知，所以不应写成“已完成 @ 消息提醒”。讨论也没有编辑、撤回或删除消息功能。

### 3.6 资源上传、下载和资料库

代码依据：[`src/pages/GroupDetail.jsx`](../src/pages/GroupDetail.jsx#L679)、[`src/pages/AllFiles.jsx`](../src/pages/AllFiles.jsx)、[`src/pages/GlobalFiles.jsx`](../src/pages/GlobalFiles.jsx)、[`server/index.js`](../server/index.js#L2526)、[`server/index.js`](../server/index.js#L2632)。

| 场景 | 测试点 | 预期结果 |
| --- | --- | --- |
| 正常 | 小组成员选择文件并上传 | 生成文件记录，列表显示名称、上传者、大小和时间 |
| 正常 | 下载已上传文件 | 下载内容与原文件一致，中文文件名可正常使用 |
| 正常 | 上传者删除自己的文件 | 数据库记录和磁盘文件同时删除 |
| 正常 | 在“资料集锦”搜索文件名 | 只搜索当前用户可访问小组的实际上传文件 |
| 正常 | 链接型资料存在时打开 `/global-files` | 显示 `shared_files` 的资料名、链接、小组和上传者 |
| 异常 | 未选择文件直接提交 | 页面提示选择文件 |
| 异常 | 未登录或 C 上传、查看、删除 A 小组文件 | 应返回 401/403；当前 `group_files` 三个接口均未做权限校验 |
| 异常 | 伪造 `uploader_id` | 应以 token 用户为准；当前接口直接相信请求体中的用户 ID |
| 异常 | 上传可执行文件或危险扩展名 | 应拒绝或限制；当前 multer 没有类型白名单 |
| 异常 | 文件记录存在但磁盘文件丢失 | 下载应给出明确错误，列表不能假装文件可用 |
| 异常 | 删除不存在文件或错误的小组/文件组合 | 返回 404，不影响其他文件 |
| 边界 | 0 字节、大文件、超长文件名、同名文件 | 应有大小和名称限制并稳定处理；当前没有文件大小限制 |
| 边界 | 中文、空格、括号和多个点的文件名 | 上传、列表和下载名称不乱码 |
| 边界 | 上传中断或数据库写入失败 | 不应在磁盘留下无数据库记录的孤儿文件 |

需要特别区分：

- `group_files`：小组详情真实上传、资料集锦、管理员资料监管实际使用。
- `shared_files`：保存链接型资料，全局资料库使用；当前前端没有找到新增链接型资料的入口，因此该页面可能长期为空。
- `/uploads` 被静态公开，知道 URL 后不需要登录也能直接下载，这不符合组内资料权限预期。

### 3.7 用户权限

前端路由守卫在 [`src/App.jsx`](../src/App.jsx#L32)，后端认证和管理员校验在 [`server/index.js`](../server/index.js#L140)。权限测试不能只看按钮是否隐藏，必须直接请求接口验证。

| 操作 | 合理预期 | 当前代码判断 |
| --- | --- | --- |
| 未登录访问普通用户页面 | 跳转登录页 | 前端有路由守卫 |
| 普通用户访问管理员页面 | 跳回普通用户页面 | 前端有守卫；管理员接口也校验角色 |
| 修改 localStorage 把自己改成 admin | 只能看到页面外壳，后台接口仍拒绝 | 后端 `requireAdmin` 能阻止 |
| 未登录创建小组 | 401 | **实际可能成功**，创建接口无认证 |
| 未登录查看小组详情 | 401 | **实际可以请求**，详情接口无认证 |
| 未登录搜索用户 | 401 | **实际可以请求并看到用户名、邮箱** |
| C 查看 A 小组成员 | 403 | **实际只要求登录，没有成员校验** |
| C 操作 A 小组任务 | 403 | **实际可读、可新增、可改状态、可删除** |
| C 查看/发送 A 小组讨论 | 403 | **实际可读取，发送时还会自动加入小组** |
| C 查看/上传/删除 A 小组实际文件 | 403 | **实际接口没有认证和成员校验** |
| C 查看/新增链接型资料 | 403 | `shared_files` 接口已有成员校验 |
| 用户处理别人的邀请或通知 | 403/404 | 通知接口按当前用户 ID 校验，逻辑较完整 |
| 非组长邀请或移除成员 | 403 | 后端有组长校验 |

| 异常 | 新密码少于 4 位 | 前端拒绝；直接调用后端时当前没有长度校验 |
| 边界 | 超长昵称、简介、超大头像 | 应限制长度和大小；当前头像以 Base64 存数据库且没有大小限制 |
| 边界 | 密码包含首尾空格 | 注册、登录和修改密码对空格处理应一致；当前处理方式不完全一致 |

### 3.10 学习空间、全局汇总和管理员后台

| 场景 | 测试点 | 预期结果 |
| --- | --- | --- |
| 正常 | 学习空间加载 | 小组、任务状态、近期资料、趋势图数据与数据库一致 |

## 4. 建议的基础测试执行顺序

这是适合初学者的手工测试顺序：

1. 先做冒烟检查：注册、登录、创建小组、新增任务、发讨论、上传下载、退出登录。
2. 再用 A、B 完成邀请、接受、移除、退出等正常业务流程。
3. 使用 C 直接访问 A 小组 URL，并在浏览器开发者工具或简单接口工具中验证越权请求。
4. 使用管理员检查后台统计和管理操作。
5. 最后补空值、重复值、无效 ID、超长文本、文件类型/大小等异常和边界场景。
6. 每条用例记录：编号、前置条件、步骤、预期结果、实际结果、是否通过、Bug 编号。

## 5. 当前代码中的明显问题与风险

以下结论均来自当前代码，运行测试时应优先验证。

### 高优先级

1. **真实文件接口完全缺少认证和权限校验。** 上传、列表、删除接口都没有 `requireAuthUser`；上传者 ID 来自请求体，删除接口也不判断上传者或组长。任何知道小组/文件 ID 的人都可能查看、冒充上传者或删除文件。依据：[`server/index.js`](../server/index.js#L2632)。
2. **上传文件可通过静态 URL 未登录下载。** `/uploads` 直接由 Express 静态公开，绕过小组成员权限。依据：[`server/index.js`](../server/index.js#L46)。
3. **普通任务接口没有小组权限校验。** 已登录用户可以获取全部任务，也可以向其他小组新增任务、修改任意任务状态、删除任意任务。依据：[`server/index.js`](../server/index.js#L1663)。
4. **讨论权限存在严重逻辑错误。** 非成员可以读取讨论；非成员发消息时，后端会自动把该用户加入小组，绕过邀请流程。依据：[`server/index.js`](../server/index.js#L2418)。
5. **Socket.IO 房间没有身份和成员校验。** 客户端只要知道小组 ID 就能加入房间并接收实时消息。依据：[`server/index.js`](../server/index.js#L60)。
6. **创建小组、小组详情和用户搜索接口未登录也可访问。** 用户搜索还返回邮箱，存在信息泄露风险。依据：[`server/index.js`](../server/index.js#L1871)、[`server/index.js`](../server/index.js#L2063)、[`server/index.js`](../server/index.js#L2819)。
7. **小组成员列表没有成员范围校验。** 任意已登录用户知道小组 ID 后，可查看该组成员的用户名和邮箱。依据：[`server/index.js`](../server/index.js#L1979)。

### 中优先级

8. **文件上传没有大小和类型限制。** `multer` 只配置了磁盘保存位置，没有 `limits` 或 `fileFilter`，可能上传超大文件或不合适的文件类型。依据：[`server/index.js`](../server/index.js#L48)。
9. **失败上传可能留下孤儿文件。** multer 会先写磁盘，再校验 `groupId`、`uploaderId` 或写数据库；后续失败时没有删除已经落盘的文件。
10. **删除小组/用户没有显式删除物理上传文件。** 数据库外键可能清除 `group_files` 记录，但磁盘中的文件不会随之删除。管理员强制解散也有相同问题。
11. **注册重复错误码与前端约定不一致。** 注册页专门处理 409，但普通注册接口把重复用户名/邮箱也返回 500，用户得到的提示和接口语义不准确。依据：[`src/pages/Register.jsx`](../src/pages/Register.jsx#L33)、[`server/index.js`](../server/index.js#L499)。
12. **注册后端缺少邮箱格式、密码强度和长度校验。** 浏览器页面的 `type="email"` 可以被直接接口请求绕过。
13. **个人资料后端没有执行与前端一致的新密码最小长度限制。** 直接请求接口可以绕过前端 4 位限制。
14. **管理员角色逻辑不一致。** 管理员页面允许创建或修改其他 `admin` 用户，但服务启动时会把用户名不是 `admin` 的用户全部改回普通用户。依据：[`server/index.js`](../server/index.js#L380)。
15. **默认演示账号密码固定。** 适合本地作品演示，但如果直接部署到公网，任何人都可能登录演示管理员账号。不能把当前版本描述为生产级安全系统。
16. **未配置 `AUTH_TOKEN_SECRET` 时，每次服务启动会生成随机密钥。** 服务重启后已有 token 全部失效。依据：[`server/index.js`](../server/index.js#L26)。
17. **接口错误状态码不统一。** 任务、小组等部分接口在失败时仍返回 HTTP 200，仅在 JSON 中写 `success: false`，不利于前端和接口测试准确判断。

### 完整性和可维护性问题

18. **两套资料功能没有统一。** 小组详情和资料集锦使用 `group_files`；全局资料库使用 `shared_files`，但当前前端没有新增链接型资料的入口。
19. **`@成员` 没有通知闭环。** 当前只做显示格式和实时消息，没有生成被提及者通知。
20. **数据库建表脚本已过时。** [`server/create-tables.sql`](../server/create-tables.sql) 使用 `groups` 表和两种任务状态，而运行时代码使用 `groups_table`、三种状态和更多表。只执行该 SQL 无法得到当前应用所需完整结构。
21. **API 地址写死为 `http://localhost:3001`。** 部署到其他地址时前端不能自动连接正确后端。依据：[`src/api/client.js`](../src/api/client.js#L1)。
22. **存在未接入路由的页面文件。** `Home.jsx`、`AdminDashboard.jsx` 容易让维护者误认为仍在使用。
23. **代码规范检查当前不通过。** `npm run lint` 结果为 34 个 error、1 个 warning，主要包括 Node 全局变量未在 ESLint 中配置、未使用变量、Effect 中同步更新状态和 Hook 依赖问题。它不一定代表项目无法启动，但说明仓库目前不能宣称“质量检查全部通过”。
24. **没有测试脚本或测试代码。** `package.json` 只有 dev、build、lint、preview，没有 `test` 命令；仓库也没有测试用例目录。
25. **README 仍是基础 Vite 说明。** 缺少项目功能、环境配置、数据库初始化、启动方式、测试账号和已知限制，不利于面试官复现项目。

## 8. 结论

这个项目适合作为应届生软件测试作品，因为它有清晰的用户角色、跨页面业务流程、状态变化、文件操作和较多可验证的权限场景。最有价值的测试主题是：

1. 小组邀请与成员关系是否一致；
2. 任务三种状态及跨小组权限；
3. 讨论历史、实时消息和非成员访问；
4. 文件上传下载删除及访问权限；
5. 普通用户与管理员的权限边界。

当前版本更适合定位为“可用于手工功能测试和 Bug 分析的学习项目”，不适合直接描述为完善或生产可用系统。下一步如果用于求职，应先按本文执行基础用例、建立 Bug 清单和测试报告，再修复高优先级权限问题；这样比添加尚未学习的高级测试技术更有价值。
