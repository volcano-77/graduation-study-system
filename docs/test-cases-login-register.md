# 登录与注册功能测试用例

## 1. 文档说明

本文基于当前项目实际源码和 [`docs/test-analysis.md`](./test-analysis.md) 编写，只覆盖项目真实存在的登录、注册、登录状态和退出功能。

代码依据：

- 登录页面：[`src/pages/Login.jsx`](../src/pages/Login.jsx)
- 注册页面：[`src/pages/Register.jsx`](../src/pages/Register.jsx)
- 登录/注册接口：[`server/index.js`](../server/index.js#L426)
- 路由登录状态判断：[`src/App.jsx`](../src/App.jsx#L33)
- 退出登录：[`src/components/Sidebar.jsx`](../src/components/Sidebar.jsx#L162)

当前注册页只有“昵称、邮箱、密码”三个输入框，没有“确认密码”输入框。因此本文不编写“两次密码不一致”用例，并将其视为项目不存在的功能，而不是遗漏测试。

### 测试类型说明

每条用例的第一个类型用于最终数量统计：`正常场景`、`异常场景`或`边界值`。后面可附加 `等价类`、`必填项`、`格式校验`，不使用高级测试方法。

### 风险标记说明

- `⚠ LR-01`：普通注册发生用户名/邮箱重复时，后端返回 500，而注册页准备按 409 处理。
- `⚠ LR-02`：后端没有邮箱格式校验，绕过浏览器页面后可能注册非法邮箱。
- `⚠ LR-03`：注册没有密码最小长度或复杂度规则，1 位密码也可能注册成功。
- `⚠ LR-04`：用户名和邮箱没有应用层长度校验，超出数据库长度时可能只得到 500。
- `⚠ LR-05`：未设置固定 `AUTH_TOKEN_SECRET` 时，服务重启会生成新密钥，使原 token 失效。

以上标记表示该用例可能暴露 [`docs/test-analysis.md`](./test-analysis.md) 已发现的问题，不代表本文已经实际执行并确认 Bug。
